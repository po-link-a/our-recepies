# Телеграм-бот: фото рецепта → страница на сайте

Мама фотографирует вырезку → бот распознаёт текст → показывает, что получилось →
она правит или нажимает «Опубликовать» → рецепт коммитится в репозиторий → Vercel
пересобирает сайт.

Код: [`api/tg/recipe.ts`](../api/tg/recipe.ts). Адрес вебхука: `https://<домен>/api/tg/recipe`

---

## Что нужно сделать руками (по порядку)

### 1. Создать бота

В Telegram напишите [@BotFather](https://t.me/BotFather):

```
/newbot
```

Имя — любое (например `Семейные рецепты`), username должен заканчиваться на `bot`.
BotFather выдаст токен вида `8123456789:AAH...`.

→ это **`TG_BOT_TOKEN`**

Полезно сразу отключить у бота групповой режим: `/setjoingroups` → `Disable`.

### 2. Ключ Gemini

Откройте [aistudio.google.com/apikey](https://aistudio.google.com/apikey) → **Create API key**.

→ это **`GEMINI_API_KEY`**

### 3. Upstash Redis (память бота между сообщениями)

[console.upstash.com](https://console.upstash.com) → **Create Database** → Redis →
регион поближе к Европе. На странице базы, в блоке **REST API**, скопируйте два значения:

→ **`UPSTASH_REDIS_REST_URL`** и **`UPSTASH_REDIS_REST_TOKEN`**

Бесплатного тарифа хватает с большим запасом.

### 4. Токен GitHub (чтобы бот мог коммитить)

[github.com/settings/personal-access-tokens/new](https://github.com/settings/personal-access-tokens/new) —
**fine-grained** токен:

- Repository access → **Only select repositories** → `po-link-a/our-recepies`
- Permissions → Repository permissions → **Contents: Read and write**
- Срок — год, потом придётся выпустить новый

→ это **`GITHUB_TOKEN`**

### 5. Развернуть на Vercel

[vercel.com/new](https://vercel.com/new) → импортировать `po-link-a/our-recepies`.
Vercel сам определит Vite, ничего менять не нужно.

Перед первым деплоем (или сразу после) добавьте переменные — см. таблицу ниже.

### 6. Придумать секрет вебхука

Любая случайная строка — она нужна, чтобы на адрес бота не мог постучаться никто, кроме Telegram:

```bash
openssl rand -hex 32
```

→ это **`TG_WEBHOOK_SECRET`**

### 7. Узнать chat id — свой и мамин

Пусть каждый напишет боту любое сообщение (`привет`), затем откройте в браузере:

```
https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates
```

В ответе найдите `"chat":{"id":123456789,...}`. Нужны все id, кто должен пользоваться ботом.

→ это **`TG_CHAT_ID`**, через запятую: `123456789,987654321`

### 8. Подключить вебхук

Один раз, из терминала (подставьте свои значения):

```bash
curl -X POST "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -H 'content-type: application/json' \
  -d '{
    "url": "https://<ваш-домен>.vercel.app/api/tg/recipe",
    "secret_token": "<TG_WEBHOOK_SECRET>",
    "allowed_updates": ["message", "callback_query"]
  }'
```

Проверить: `https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo` — там должно быть
`"pending_update_count": 0` и пустой `last_error_message`.

## Переменные окружения

Vercel → проект → **Settings → Environment Variables**. Включите все три окружения
(Production, Preview, Development).

| Переменная | Что это | Откуда | Пример |
| --- | --- | --- | --- |
| `TG_BOT_TOKEN` | токен бота | шаг 1, @BotFather | `8123456789:AAH...` |
| `TG_CHAT_ID` | **кому можно писать боту** | шаг 7, `getUpdates` | `123456789,987654321` |
| `TG_WEBHOOK_SECRET` | подпись запросов Telegram | шаг 6, придумать | `a3f9...` |
| `GEMINI_API_KEY` | **распознавание фото** | шаг 2, AI Studio | `AIza...` |
| `UPSTASH_REDIS_REST_URL` | состояние черновика | шаг 3 | `https://eu1-...upstash.io` |
| `UPSTASH_REDIS_REST_TOKEN` | то же | шаг 3 | `AX...` |
| `GITHUB_TOKEN` | запись в репозиторий | шаг 4 | `github_pat_...` |
| `GITHUB_REPO` | куда коммитить | вписать вручную | `po-link-a/our-recepies` |
| `GITHUB_BRANCH` | ветка | необязательно | `main` (по умолчанию) |
| `SITE_ORIGIN` | для ссылки в ответе боту | ваш домен | `https://our-recepies.vercel.app` |

**Все ключи живут только здесь, в настройках Vercel.** В репозиторий их класть нельзя —
`.env` файлов в проекте нет и заводить их не нужно.

`TG_CHAT_ID` — единственная защита от посторонних. Если она пустая, бот молча
игнорирует всех, включая вас.

После изменения переменных нужен **Redeploy** — на лету они не подхватываются.

## Как этим пользуется мама

1. Присылает боту фото вырезки (можно сразу несколько — если рецепт на двух страницах).
2. Бот отвечает разобранным рецептом: название, категория, ингредиенты, шаги.
3. Кнопки под сообщением:
   - **✅ Опубликовать** — рецепт уходит на сайт, через 1–2 минуты приходит ссылка
   - **✏️ Исправить** — поправить название, категорию, ингредиенты, шаги, время, порции, источник
   - **📷 Добавить фото** — дослать ещё страницу того же рецепта
   - **🔄 Распознать заново** — если разбор получился плохим
   - **✖️ Отмена** — выбросить черновик

Команды: `/help` — как это работает, `/cancel` — отменить текущий рецепт.

## Что происходит при публикации

Одним коммитом:

- в `src/data/recipes.json` добавляется рецепт (в начало — он попадёт в «Недавно добавленные»)
- в `public/scans/<slug>.jpg` кладутся оригиналы фото

Фото показываются на странице рецепта под шагами приготовления, подписью
«оригинал вырезки».

Новые рецепты помечаются `isArchive: true` и попадают в раздел «Бабушкин архив».
Если модель не смогла что-то разобрать — рецепт получает пометку о неполном скане,
как у остальных архивных вырезок.

Ссылка, которую бот присылает — `https://<домен>/#/recipe/<slug>`.

## Если что-то не работает

**Бот молчит.** Скорее всего ваш chat id не в `TG_CHAT_ID`, либо после её изменения
не сделали Redeploy. Проверьте логи: Vercel → Deployments → Functions → `api/tg/recipe`.
Отказ пишется как `rejected chat <id>`.

**«Что-то пошло не так: GitHub … 403».** У токена нет прав `Contents: write`, либо
он выпущен не на тот репозиторий, либо истёк.

**Vercel отказывается деплоить коммит от бота.** Коммит подписывается вашей учётной
записью GitHub через токен — если у неё нет доступа к проекту Vercel, деплой не запустится.

**Распознало плохо.** Нажмите «🔄 Распознать заново» — модель не детерминирована,
второй проход часто выходит лучше. Если не помогает, лучше переснять: ровный свет,
без бликов, текст целиком в кадре.

**Изменения не появились на сайте.** Проверьте, что коммит долетел:
`git log --oneline -3` в репозитории. Затем — что деплой прошёл на Vercel.
